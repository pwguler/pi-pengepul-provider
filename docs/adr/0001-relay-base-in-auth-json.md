# Relay base lives in auth.json, not env or models.json

The provider needs a relay base URL that a user can set once per machine. It lives as a top-level `baseUrl` field on the pengepul credential in `~/.pi/agent/auth.json`, beside the API key. pi ignores the field — only the extension reads it — but `auth.json` is the one file the user already edits for this provider, and it is written by the login flow, which is where a hand-edited field would otherwise go stale. Alternatives were rejected: an env var needs shell configuration the user asked to avoid; `models.json` is a second file, and pi does not apply its provider `baseUrl` to extension-supplied models; the credential's `env` map is pi's documented place for provider-scoped values, but it reads as interpolation plumbing rather than configuration.

Consequences: `/login pengepul` must prompt for the URL and write it, since pi replaces the whole credential object on login and a key-only login would silently delete the field. `providers.pengepul.baseUrl` in `models.json` must not be set: with a native provider it rewrites every model's baseUrl to one value, collapsing the Anthropic Messages and OpenAI Chat Completions dialect split.
